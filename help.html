1. Playing

Open the launcher, pick an installation on the left, press PLAY. The first load of a version is slow — a client is tens of megabytes and, on the real-JVM route, a Java runtime is downloaded and started — but it is cached afterwards, so the second time is quick.

Controls are the game's own: keyboard and mouse are captured once the game window has focus. Click the page first if the keyboard does nothing. Full screen is F11 or the game's own option.

Older versions are the easier and faster path: they run the original game with Fabric at play time. Newer ones have to be compiled because the browser runtime's Java is older than theirs.

3. Your own mods

There is no list of mods to choose from on purpose — the mods are yours. Drop the .jar files you already use into the launcher (or add them in New installation).

  • Real Java installations: your mods load at play time, exactly as in a normal launcher. Fabric and Fabric API are provided by the page.
  • Compiled installations: the client has to be rebuilt with your mods inside it, so a build runs first. When it finishes, the row becomes your client and PLAY opens it.

Mods come from anywhere you got them: CurseForge, Modrinth, GitHub releases. Nothing is uploaded to a server you did not choose — see Building for exactly where they go.

4. Building

A bake is a real compile: it needs a JVM, a compiler and 30–45 minutes. That cannot happen in the browser, so it happens on GitHub Actions, and the launcher has to be able to start a run. Starting a run needs a token; a web page cannot hold one safely, and this page does not pretend otherwise. You have three options:

OptionWhat it needsBest for
Your own GitHub token a fine-grained token for the repository, kept in your browser builds right now, no server of your own
A build service (Cloudflare Worker or Deno) one deployment holding the token for everybody a public launcher other people use
A local service node tools/build-service.mjs on this computer testing

5. The GitHub token, step by step

Read this first

The token is a password for your GitHub account, limited to one repository. Anyone who has it can change that repository. The launcher stores it in your browser's own storage and sends it nowhere except api.github.com — you can see that in the page's source, and Forget token removes it. Do not paste a token into a page you did not open yourself.

  1. Sign in to GitHub and open Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new.
  2. Token name: anything, e.g. webmc build.
  3. Expiration: 7 or 30 days is plenty. Short is better.
  4. Repository access: Only select repositories → the WebMC repository (AmphibianDev/webmc-port).
  5. Permissions → Repository permissions:
    • Contents: Read and write — the mods are committed to a branch of that repository.
    • Actions: Read and write — this is what starts the build, and reads its result.
    Everything else can stay No access.
  6. Generate, copy the token (it begins github_pat_).
  7. In the launcher: New installation → How should this build run? → GitHub, with my own token → paste it → Build.

What the page then does, in order, all of it visible in your browser's network tab:

GET  /repos/<repo>/git/ref/heads/main                    read the current branch
POST /repos/<repo>/git/refs                             create build/<key> from it
PUT  /repos/<repo>/contents/mods/vendor/<mod>.jar       your mods, on that branch only
PUT  /repos/<repo>/contents/build-info.json              which version this build is for
POST /repos/<repo>/actions/workflows/…/dispatches        start the bake on that branch
GET  /repos/<repo>/actions/runs?branch=build/<key>       poll until it is done

The branch is named after the content of your mod set, so asking for the same mods twice reuses the first build instead of starting another. Your mods are never committed to main.

Watch the build yourself at the repository's Actions page — the launcher's log is a summary of the same run.

6. Running a build service instead

If the launcher is for other people, keep the token out of their browser: deploy one small endpoint that does the same calls. gateway/build-worker.js in the repository is exactly that, for Cloudflare Workers:

npx wrangler deploy gateway/build-worker.js --name webmc-build --compatibility-date 2026-01-01
npx wrangler secret put GITHUB_TOKEN      # the same fine-grained permissions as above

Then put its address in clients.json as build.service and the launcher's Build machine field will already be filled in. For testing there is also a local one:

cd webmc-mods && node tools/build-service.mjs      # listens on 127.0.0.1:8787

7. What cannot be baked

Mods with native libraries cannot work in a browser at all. Distant Horizons is the well-known one: it ships Windows, macOS and Linux binaries, and a page has no way to run them. The launcher refuses these in a second, before a build starts, with that reason — rather than leaving you waiting 45 minutes for a build that was never going to run.

Two more honest limits:

  • A mod that mixes into another mod's classes needs that other mod in the same build. Put both jars in and they are baked together, which is how such mod sets are meant to be installed.
  • A mod written for a different Minecraft version is skipped by the game's own loader. Nothing is "fixed" silently: if a mod is skipped, the game says so and the log names it.

8. Which versions are listed, and why

Only versions that actually run in a browser appear in the list. That is decided from each version's own metadata, not from a hand-written list:

  • LWJGL 2 with Java 8 or older → it runs: the official jar in the page. That is 1.0 through 1.12.2, plus the snapshots in that window — 349 of them.
  • LWJGL 3 → it would need a JavaScript version of LWJGL 3, which is being written but is not finished. Those versions are not offered.
  • Java 21 or newer → newer than the Java a browser runtime provides; they are compiled instead (26.2, 26.3, 1.21.11 today).
  • Alpha and beta → they need fixed-function OpenGL, which WebGL does not have.

95 further versions can be built on demand; they are listed in the New-installation version box with "no build yet — this will start one".

9. When something goes wrong

The page stays empty, or says the runtime could not load

CheerpJ (the Java runtime in the page) is a script downloaded from cjrtnc.leaningtech.com. An ad-blocker, a strict content-security policy, an offline network or an HTTPS-only extension can stop it. The page says which of those happened; try a normal window with the blocker off.

The build failed

Open the run from the link in the log — that is the real error. Then check, in order: was the version spelled the way the list spells it (26.2, not 1.26.2); does the token have Actions: Read and write as well as Contents: Read and write; is the token expired. A 403 in the log is almost always a permission, a 404 a repository name.

The build worked, but PLAY opens the old client

The published page is cached by the browser. Add the row again from the build's log link, or reload with cache disabled. The version list's compiled rows always point at the newest published build.

A mod has no effect

Mods that need Fabric API and did not get it will fail on their own terms — the game's log names them. Some mods also require a mod menu or a config screen mod to do anything visible.

10. Accounts, privacy, legality

  • This is not an official Minecraft product. It is not approved by or associated with Mojang or Microsoft. You need to own Minecraft to play it — the client jar is downloaded from Mojang's own servers when you play, and never redistributed here.
  • Multiplayer works through a relay when a server is joined from the page; the relay forwards bytes and never holds a key, and it refuses anything that is not a Minecraft session.
  • Your token stays in your browser's storage, is sent only to api.github.com, and can be removed with Forget token.
  • Your mods are committed to a branch of the build repository (so the build can use them) and are public there, as anything in a public repository is. If that is not acceptable for a private mod, run a build service of your own instead, or play a version whose mods load at play time.
  • No analytics, no accounts, no tracking on these pages.
